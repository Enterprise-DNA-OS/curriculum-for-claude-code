# Why there is no front end

This base is an academic review desk. The operator asks for overdue reviews, incomplete outcome mapping and credit gaps. The CLI reads the database, and the existing renderer produces private read-only HTML. A coding agent turns a plain-language request into the documented operation.

Akari supplies a broader institutional suite with collaborative curriculum work, publication and integrations. This base does not reproduce those interfaces. It holds the records and review workflow for a small trusted curriculum team.

## Where screens matter

A mobile app gives staff guided entry and a screen designed for small devices. This base has no mobile capture, offline synchronisation, drag-and-drop mapping or simultaneous visual editing. PGlite is a local single-process database. A shared PostgreSQL deployment still needs institution-specific identity, permissions and operating procedures. Actor labels alone do not provide those controls.

The HTML views and documents are snapshots. They cannot approve a programme or edit its records. Regenerate them after changes. For a live catalogue, browser editor or institution-wide rollout, Enterprise DNA scopes the screens and connections on the same records.

## Where this fits

A curriculum owner can prepare an evidence review without a new interface, keep version history readable and change rules with a tested migration. The database and MIT-licensed code remain under the institution's control. Hosting, backups, agent subscriptions and operating time still have costs.
